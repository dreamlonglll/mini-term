# 允许移动端发起新的 AI 会话（只经桌面端具名启动器），并给桌面端接入中转加鉴权

ADR 0001 定下的边界是"移动端只能驱动人已经在桌面开好的 AI 会话"。实际使用中这条边界卡在一个很常见的位置：人离开电脑后想开一个**新**任务，必须先回到电脑前把 agent 拉起来，远程能力只覆盖了"续"而没覆盖"起"。决定放宽这一条——移动端可以在任意项目里发起新的 AI 会话，但发起方式被死死限制为**引用桌面端配置的具名 AI 启动器**：启动器是 `{名称, shell（可选，缺省用默认 shell）, 命令}`，配置只存在于桌面端，移动端传的是启动器 id，命令文本从不经过移动端或中转。

同时把一个 v1 遗留的洞一并修掉：中转的 `/ws/desktop` 端点此前没有任何鉴权，握手只校验协议版本，且新连接顶替旧连接——任何知道中转地址的人都能冒充桌面端，顶掉真桌面、收走移动端指令、还能索取配对码顶掉手机凭证。本次协议本就要 bump 到 v2、中转本就要重新部署，是修它边际成本最低的一次窗口。桌面端 Hello 起携带部署方配置的共享密钥，中转未配置密钥时**拒绝一切桌面连接**（fail-closed），而不是放行。

## 关键边界（放宽了什么、没放宽什么）

- 放宽的只有"不能远程启动新 AI 会话"这一条。**裸 shell 依然不可见、不可驱动**，移动端依然不能远程执行任意命令。
- 启动命令不可由移动端自拟。哪怕后端拿"首词必须是 claude/codex/opencode"去校验也挡不住 `claude && 任意命令`——首词合法而整行照样进 shell。所以校验不是防线，**"命令只能来自桌面端配置"才是防线**。
- 新会话落成一个新 tab，但**不抢桌面界面焦点**：不切当前项目、不切当前 tab。代价是该 pane 在桌面终端里的早期输出会丢（xterm 实例要等项目被挂载才创建），对话镜像不受影响——它读的是会话记录 JSONL。
- 启动失败（命令不存在 / 未登录 / 卡在交互确认）时 pane **保留不杀**：分不清"起不来"和"起得慢"，杀掉的破坏性大于留着。
- SSH 远程项目与 WSL 根项目的入口**置灰**：这类项目的对话镜像目前一定是空的（`mobile_mirror.rs` 的 v1 限制：仅本机 Windows 宿主来源），在那里开会话只能盲发指令、看不到回复。
- 桌面端新建时弹一次通知。凭证被盗时这是唯一的审计迹象。

## 被否决的备选

- **移动端自由输入启动命令**：等于变相开裸 shell，与上一条边界直接冲突。
- **给移动端加"关闭这个 pane"**：能顺手收拾启动失败的残局，但等于把"远程 kill 你正在跑的终端"送给了任何拿到凭证的人。
- **新建后把桌面切过去**：桌面输出从第一帧就完整，代价是远程操作会改动你桌面上正在看的现场。
- **让新建的 pane 立刻进快照（pending 态、可见不可驱动）**：断线重连后仍能看到它、失败不会变成隐形孤儿 pane；代价是可见性规则要多出"可见但不可驱动"的第三类 pane，安全边界从一条线变成一张表。改用"回执 + 手机本地启动中态 + 超时提示"，规则一条不动。
- **协议不 bump、靠旧端静默忽略未知消息**：新手机配旧中转会表现为"点了没反应"，正是 ADR 0001 反对的静默错乱。
- **桌面端鉴权靠"中转地址保密"**：PWA 就托管在中转上，地址早已躺在手机浏览器历史里，保密不是边界。
- **桌面端鉴权单独立项**：洞会多开一段时间，且下次还得再 bump 一次协议、再重部署一次中转。
