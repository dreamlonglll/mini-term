# 允许 AI 会话作为编排者驱动其他 AI 会话（能力经启动器显式授予，可见范围仅限其自启的会话）

移动端中转体系已经走通了「看状态 → 按启动器开会话 → 写穿指令 → 读对话镜像」这条控制链路，控制端是手机上的人。本决定为这条链路增加第二类消费者：**本地 pane 里跑着的 agent**——用户开一个「编排者」会话（如 Claude Code），它通过本地控制命令启动并调度其他异构 agent（Codex / Grok / opencode / pi…），每个被启动的 agent 都是桌面上一个真实可见、可随时人工接管的终端 pane。与各家 agent 自带的黑盒 subagent 相比，卖点有三：异构（各用各的长处与订阅额度）、全程可见可干预、移动端镜像白捡（手机上能看整个编排现场）。

控制端从「人」换成「LLM」，边界必须比移动端更紧。三条核心边界如下。

## 关键边界

- **信任根：编排能力经 AI 启动器上的「允许编排」开关显式授予**。勾了开关的启动器起 pane 时，编排令牌与该 pane 的自身身份随 PTY 环境变量注入；控制 CLI 无令牌即拒绝（fail-closed，与 SSH 能力令牌同姿势）。自身身份随环境钉死，自指禁令（不许驱动自己的 pane）不需要任何猜测。
- **可见与可驱动范围：仅限编排者自己启动的受编排会话**。比移动端那条「所有 AI 会话可见」的线更紧：用户亲手开的会话、其他编排者的会话、裸 shell 一律不可见不可驱动。由此「编排者干的一切都发生在打了出身标识的 pane 里」，责任边界一刀切干净。
- **跨项目范围：本项目 + 同分组项目**。搭 issue #44「分组即工作区」的便车：前后端拆成两个项目的用户，把它们拖进同一分组即表达了「这是一件事」，编排边界零新增配置。未分组项目只能在本项目内编排。
- **启动方式沿用 ADR 0002 的防线**：编排者只能按 id 引用具名启动器，不能自拟命令文本——「命令只能来自桌面端配置」仍是唯一防线。
- **受编排会话出身不构成状态**（与「移动端发起的会话」同构）：编排者退出，它们照常活着，标识转为「编排者已离场」；MVP 不做「重新收养」——编排者 pane 重启即新身份，够不到前世的会话，孤儿由用户人肉处理。
- **attention 不代答**：受编排会话停在等审批/提问时，编排者的等待命令立即返回该状态与原因，由编排者在自己的对话里播报、用户亲自去乐手 pane 处理。不加新 UI（既有黄灯徽章 + 编排者播报已足够），编排者代答不设开关、不存在。
- **任何启动器都能当乐手，读结果按能力分层**：结构化会话记录仅 Claude/Codex/Grok 可读（与镜像的既有口径同构），全员兜底一个「读终端画面尾部文本」的原语。opencode/pi 是「有状态徽章、无对话记录」的既有二等公民待遇，编排层照抄，不发明新规则。
- **同时存活的受编排会话有硬上限**（默认 5，设置可调）：超限的启动请求返回明确错误给编排者，让它自己调度排队；不静默排队。上限只计活着的 AI 会话，乐手退出即释放名额。
- **出生礼仪沿用 ADR 0002**：新会话落成新 tab，不抢焦点不切项目，诞生一次性提示，tab 带「受编排」出身标识。

## 被否决的备选

- **令牌放数据目录文件、任何 pane 都能调控制 CLI（环境自由）**：受编排会话里的 agent 同样读得到令牌，「禁止套娃编排」就只剩君子协定；且 CLI 无法可靠知道「我是哪个 pane」，自指禁令要靠猜。
- **可驱动范围对齐移动端（所有 AI 会话可驱动)**：移动端背后是用户本人，编排者背后是 LLM。往用户聊到一半的会话里塞 prompt 是对话劫持；用户的对话记录被喂给编排者是隐私面与提示注入面的双扩大。「把已有会话交给编排者」若有真需求，留二期做成用户侧显式动作。
- **跨项目全列表可达**：等于把「LLM 可以在我任何项目里起进程」写进威胁模型；项目列表里躺着的无关项目不该在爆炸半径内。
- **跨项目显式配置项目集**：配置摩擦大，且与分组语义重复造轮子。
- **编排者退出时自动关闭其受编排会话**：乐手 pane 里可能躺着改到一半的代码与诊断结论，大脑崩了就烧现场等于毁尸灭迹；也违背「出身不构成状态」。
- **MVP 只许 Claude/Codex/Grok 当乐手**：砍掉异构编排这个核心卖点，还得引入「按启动器命令文本分类 agent 家族」的门禁分类器，多一套分类多一处漏。
- **attention 时编排者可代答（哪怕加显式开关）**：大脑给自己的乐手批权限等于自我越权，审批这道闸的意义就没了。
- **控制面走 MCP**：本仓 SSH 线已经从 MCP 迁到 CLI+Skill（工单 07 计划下线 MCP）；CLI+Skill 对 Codex/Grok 这类不便挂 MCP 的 agent 也天然可用，编排控制面走同一条路。
