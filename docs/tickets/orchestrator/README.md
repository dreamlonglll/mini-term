# 编排者（Orchestrator MVP）工单

规格（PRD）在 issue [#61](https://github.com/dreamlonglll/mini-term/issues/61)，边界决策在 `docs/adr/0003-ai-session-orchestration.md`，领域词条见 `CONTEXT.md`（编排者 / 受编排会话）。

每张工单是一发 tracer bullet：纵切所有层、可独立演示。按 frontier 开工——阻塞项全部完成的票即可动工，每张票用一个新会话实施。

## 依赖图

```
01 前置重构 ──┐
              ├─→ 03 启动乐手 ─→ 04 标识/离场 ─┐
02 追踪弹  ──┘        │                        │
                      ├─→ 05 send ─────────────┤
                      ├─→ 06 wait ─────────────┼─→ 09 Skill+验收（收口）
                      ├─→ 07 读结果 ───────────┤
                      └─→ 08 上限设置 ─────────┘
```

- **01、02** 互不阻塞，可立即并行开工
- **03** 是汇合点
- **04–08** 五张全部并行
- **09** 收口

| 票 | 标题 | Blocked by |
|----|------|-----------|
| 01 | 前置重构：抽出「按启动器起会话」共享入口 | 无 |
| 02 | 追踪弹：编排能力授予 + 控制面骨架 + CLI 首命令 | 无 |
| 03 | 启动乐手：start-session + 范围/上限/套娃裁决 | 01, 02 |
| 04 | 受编排标识与「编排者已离场」态 | 03 |
| 05 | 派活：send 写穿（bracketed paste 多行） | 03 |
| 06 | 等待：wait 长轮询四类终态 | 03 |
| 07 | 读结果：read-transcript + read-screen | 03 |
| 08 | 乐手并发上限设置项 | 03 |
| 09 | 编排礼仪 Skill + 端到端真机验收（收口） | 04–08 |
