# 远程文件管理与项目路径选择优化

## Goal

让左下角文件管理器在本地与远程会话下都具备接近 VS Code 的一致交互，并让左上角新建远程项目既可手动输入路径，也可浏览选择远程目录。

用户应能明确区分“对当前条目操作”和“对当前目录空白处操作”，完成常用文件传输与目录操作，且所有远程动作都作用于远端而不是误落到本机。

## Background

- 远程文件管理中，新建文件和新建文件夹当前无效。
- 文件树空白处右键时，菜单仍错误地绑定到某个文件或文件夹。
- 远程文件管理中显示的“在文件夹中打开”会打开本机桌面目录，语义和行为都不正确。
- 左上角新建远程项目当前只能手动输入路径，缺少远程目录浏览与选择能力。
- 需要确认现有递归删除的实现方式，并评估删除包含大量文件的目录时是否会阻塞界面或明显变慢。

## Confirmed Facts

- 文件树目前只有目录读取通过 `remote_ssh::list_directory_for` 区分本地与远程；新建、重命名、删除、默认程序打开和系统文件管理器定位均无条件调用本机实现。这既会令远程操作失败，也存在远端 POSIX 路径恰好在本机存在时误操作本机同名路径的风险。
- 新建失败当前只写 stderr，没有用户可见错误，因此表现为“点击无效”。
- 本地删除链路为确认框 → 后台执行器 → `std::fs::remove_dir_all/remove_file`。它不直接阻塞 GPUI 渲染线程，但没有进行中反馈，且大目录删除会长期占用后台工作线程并产生大量 watcher 事件。
- 本地删除目前会 canonicalize 并跟随叶子符号链接，可能删除项目内被链接的真实目录而留下断链；这是本任务必须修复的数据安全缺陷。
- 远程删除当前并未实现；若直接使用串行 SFTP 递归，大目录会产生与条目数线性相关的网络往返，必须采用服务端操作或有明确上限/计数验证的复用策略。
- 文件树目录加载的异步结果只按 `PathBuf` 回写，没有校验项目和连接身份；两台服务器使用相同路径时，切换项目后的迟到响应可能污染当前树。
- 现有 `AppStore::new_terminal_with_cwd` 可复用，但 SSH 启动分支错误地固定使用项目根，忽略传入的子目录工作路径。
- 新建远程项目的现有保存链路已经通过 SFTP canonicalize/stat 校验路径，并以 `ssh_connection_id + canonical POSIX path` 存储，不需要修改配置格式。
- 当前没有可复用的远程目录选择器；项目文件树带活动项目、`.gitignore` 和固定隐藏目录语义，不适合直接嵌入。应新增轻量选择器并复用连接池与 SFTP 原语。
- GPUI 已把操作系统文件拖放统一转换为 `ExternalPaths`，项目列表和终端区已有正确的 `on_drag_move/on_drop` 范例；远程文件树可直接复用该基础设施，不需要平台专属拖放实现。
- `dirs` 依赖已经存在于 `mt-config` 与 `mt-app`，可用其系统下载目录解析能力；配置应只保存用户覆盖值，未覆盖时动态使用系统默认目录。

## Requirements

- R1：修复远程会话中的新建文件和新建文件夹功能，操作目标为当前远程目录，完成后文件树正确刷新并显示新条目。
- R2：区分条目右键与文件树空白处右键：
  - 条目右键菜单以被点击文件或文件夹为目标。
  - 空白处右键菜单以当前展示目录为目标，不继承悬停项、选中项或上一次右键目标。
- R3：远程会话不得展示或执行会误打开本机目录的“在文件夹中打开”；替换为适用于远程上下文的操作。
- R3.1：远程上下文不得继续展示或执行其他本机专属动作，包括使用本机默认程序打开远程路径；本地专属能力必须由明确的文件系统类型守卫控制。
- R4：新增复制与粘贴，支持文件和文件夹，并明确粘贴目标目录；本地与远程上下文保持一致的菜单规则。
- R5：新增下载与上传：
  - 下载将远程文件或文件夹保存到设置中的本地下载目录；未配置时使用当前操作系统的用户“下载”目录。
  - 上传菜单分别提供“上传文件…”与“上传文件夹…”，将本地条目写入目标远程目录。
  - 上传除菜单选择外，还支持把本机文件或文件夹直接拖入远程文件树。
  - 上传或下载遇到同名目标时，允许用户选择“跳过”“覆盖”或“生成副本”；批量操作应允许将本次选择应用到后续冲突。
  - 完成后刷新受影响目录，并对冲突、失败和取消给出可理解的反馈。
- R6：新增“在终端中打开该文件夹”：
  - 对文件夹执行时，以该文件夹为工作目录。
  - 对文件执行时，以其父目录为工作目录。
  - 本地目标打开本地终端上下文，远程目标打开对应远程连接的终端上下文。
- R7：左上角“新建远程项目”保留手动输入远程路径，并新增远程目录浏览/选择入口；选择器必须浏览当前远程连接，不能调用本地目录选择器冒充远程选择。
- R8：尽可能复用远程文件管理已有的目录加载、路径规范化、连接身份与错误处理能力，使远程项目路径选择和文件树行为一致。
- R9：检查并记录现有删除功能的调用链、执行线程/异步模型和递归策略；通过代码与针对性验证确认大量文件目录删除是否会阻塞 UI 或产生不可接受的逐项往返开销，必要时纳入优化。
- R10：把文件操作上下文显式建模为本地、远程或断链远程，并绑定项目 ID、连接 ID、项目根和操作目标；异步结果回写前必须验证请求代号与当前上下文，禁止迟到请求跨项目/跨服务器污染。
- R11：修复本地删除对叶子符号链接的跟随行为；删除符号链接本身，不递归删除其指向目标。远程递归删除和复制同样不得跟随符号链接进入目标目录。
- R12：修复远程重命名与删除，使已经显示在远程菜单中的写操作真实作用于远端；所有失败均提供可见反馈。
- R13：长耗时复制、上传、下载和删除须显示进行中状态，阻止同一目标的重复提交，并在后台完成；操作结束后只刷新仍属于原项目/连接的受影响目录。
- R14：新增可配置的本地下载目录：默认值按操作系统解析用户“下载”目录，设置页允许浏览选择及恢复系统默认值，并对不存在、非目录或不可写路径给出反馈。
- R15：外部文件拖放仅在远程文件树中解释为上传；拖到目录行时以上述目录为目标，拖到文件行时以文件父目录为目标，拖到真正空白处时以项目根为目标。
- R16：本任务不在开发机执行 Rust 编译、Clippy 或测试；新增独立 GitHub Actions CI，在普通分支推送、Pull Request 和手动触发时完成受影响工作区的编译检查与测试，并以其结果作为 Rust 质量门。

## Constraints

- 不改变现有连接配置和项目数据的兼容格式，除非代码证据表明必须新增向后兼容字段。
- 所有远程文件操作必须绑定明确的远程连接与远程路径，不得回退为本地文件系统动作。
- 空白处菜单不得隐式操作当前选中项。
- 长耗时文件操作不得在 UI 渲染线程同步执行。
- 远程路径在服务边界内使用 POSIX 字符串规则，不能使用宿主操作系统的 `Path::join` 解释远端路径。
- 默认不跟随符号链接递归复制或删除。
- 不在本地运行 `cargo check`、`cargo build`、`cargo clippy` 或 `cargo test`；本地只允许 i18n 生成/幂等性、JSONL、静态搜索和 `git diff --check` 等不编译 Rust 的检查。
- 现有 `release.yml` 只服务 `v*` 标签发布，不把打标签作为功能验证手段；日常验证由独立 CI workflow 承担。

## Acceptance Criteria

- [ ] AC1：连接远程主机后，可在当前目录成功新建文件与文件夹，刷新后仍存在；失败时显示远程错误而非静默无效。
- [ ] AC2：分别在文件、文件夹和空白处右键时，菜单项与操作目标正确；空白处操作不会删除、重命名、下载或复制任一条目。
- [ ] AC3：远程上下文不再通过“在文件夹中打开”打开本机桌面或其他本机目录。
- [ ] AC3.1：远程菜单不再提供其他会把远程路径交给本机程序的无效动作。
- [ ] AC4：可在当前项目同一文件系统内复制并粘贴文件/文件夹；同名时生成无损副本，切换项目后不会误粘贴到同路径的另一项目或服务器。
- [ ] AC5：可上传本地文件/文件夹到远程目标目录，并可将远程文件/文件夹下载到已配置的本地下载目录；取消文件选择不会产生副作用。
- [ ] AC5.1：上传/下载发生同名冲突时可选择跳过、覆盖或生成副本；批量操作可将选择应用到剩余冲突，且不会静默覆盖。
- [ ] AC5.1a：目录选择覆盖时递归合并并覆盖同名冲突项，目标独有内容保持不变；选择生成副本时创建完整的新同级目录。
- [ ] AC5.2：把本机文件或文件夹拖到远程目录行、文件行或空白处时，分别上传到该目录、文件父目录或项目根；本地项目不误触发远程上传。
- [ ] AC5.3：未配置下载目录时下载到系统用户“下载”目录；修改设置后新下载使用新目录，取消或无效设置不破坏上一个有效值。
- [ ] AC6：可从文件树对文件夹或文件的父目录打开新终端，且本地/远程工作目录和连接上下文正确。
- [ ] AC7：新建远程项目时，可在“手动输入路径”和“浏览远程目录”之间选择；浏览所得路径能正确回填并创建项目。
- [ ] AC8：文件树刷新、错误提示和操作中状态不会令界面长时间无响应。
- [ ] AC9：删除实现与性能结论有代码锚点和验证记录；若发现 UI 阻塞或高往返递归，修复后用测试或可重复命令验证。
- [ ] AC10：操作或目录加载期间切换项目/SSH 连接后，旧请求结果不会写入新项目；相同远程路径在不同连接之间不串数据。
- [ ] AC11：删除指向项目内/外目标的文件或目录符号链接时，只删除链接自身，目标内容保持不变。
- [ ] AC12：远程重命名和删除可正常完成；远程项目根不可被删除，`..` 或符号链接不能绕过项目根边界。
- [ ] AC13：GitHub Actions 可在非发布分支/PR 上运行 Rust 编译检查与测试并通过；交付记录包含对应 workflow 结果，本地记录中不存在 Rust 编译或测试命令。

## Out of Scope

- 远程文件内容预览、在线编辑、远程全文搜索和远程 Git 状态支持。
- 跨不同 SSH 主机的直接远程到远程传输协议。
- 全局配置写盘失败反馈机制的重构。
- 为所有文件操作新增可取消、可恢复的持久化任务队列。

## Key Decisions

- 复制/粘贴限定在当前项目同一文件系统内；跨本地/远程使用明确的上传/下载。
- 上传/下载冲突策略为“跳过、覆盖、生成副本”，不得静默覆盖。
- 同名目录选择“覆盖”时递归合并，仅覆盖同名冲突项并保留目标独有内容；选择“生成副本”时创建新的完整同级目录。
- 一次批量传输出现多个冲突时，用户选择的策略应用于本批剩余冲突，避免大型目录连续弹出大量对话框。
- 外部拖放仅在远程文件树解释为上传：目录行落到该目录，文件行落到父目录，真正空白处落到项目根。
- 下载目录配置保存为可选覆盖值；未配置时动态解析系统用户下载目录。
